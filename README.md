# Reusable Shell Utilities

Bash helpers you can source into your shell. Files meant for sourcing use the `*_ref.sh` suffix; run `init.sh` once to wire selected files into `~/.bashrc`.

## Setup

```bash
./init.sh
```

You will be prompted to choose which `*_ref.sh` files to include. Options:

- numbers — e.g. `1` or `1 2` / `1,2`
- `a` — include all
- `q` — cancel

Then open a new shell, or run `source ~/.bashrc`. Re-run `./init.sh` whenever you add a new `*_ref.sh` and want it loaded.

## Files

### `init.sh`

Installer (not sourced every session). Lists `*_ref.sh` files in this folder, lets you pick which ones to load, and writes a marked block at the end of `~/.bashrc` that sources those files. Safe to re-run; it replaces the previous block.

### `init_nvim.sh`

Installs the NvChad-based Neovim config from [`nvim/`](nvim/) and bootstraps plugins. Requires Neovim on `PATH`.

```bash
./init_nvim.sh
```

Behavior:

- Symlinks `~/.config/nvim` → this repo’s `nvim/` folder
- If an existing config is present (and is not already that symlink), moves it to `~/.config/nvim.bak.<timestamp>`
- Regenerates the LuaSnip Kotlin snippets from the canonical Android templates (`android/studio/templates/`)
- Runs `nvim --headless "+Lazy! sync" +qa` so Lazy / NvChad plugins install

Safe to re-run: if the symlink already points here, it skips re-linking and re-runs Lazy sync.

### `nvim/`

Vendored Neovim config (NvChad v2.5 starter plus local customizations: mappings, nvim-tree, treesitter, LSP for Python/web). This is the source of truth used by `init_nvim.sh`.

### `android/studio/`

Android Studio live templates for Jetpack Compose and architecture, generated from canonical code bodies — and their LuaSnip equivalents for Neovim.

- `templates/*.template.kt` — single source of truth: commented Kotlin bodies with `$Variable$` markers and `$END$`
- `templates/generate.py` — emits `compose_templates.xml` (Comp Form / Detail / Card / Text Field) and `architecture_templates.xml` (Domain Model / Repository / Use Case / Room Entity & DAO / DTO / API / Repository Impl / ViewModel / Nav Graph), then merges them into `nvim/snippets/kotlin.json`
- `templates/generate.sh` — regenerate everything: `bash android/studio/templates/generate.sh`
- `templates/generate_snippets.sh` — regenerate only the nvim snippets (called by `init_nvim.sh`)
- `install.sh` — copy the XML templates into every installed Android Studio `templates/` folder

Template details: XML uses `&#10;` for newlines and `$VAR$` / `$END$` for live-template expansion. LuaSnip converts these to `${N:default}` tabstops, maps `$END$` to `$0`, and escapes literal `$` (Kotlin string interpolation) as `\$`.


### `git_ref.sh`

Git helpers scoped to the current author (`git config user.email`). Provides:

#### `git-ls`

Lists unique file paths touched by your commits in a date range (defaults to today).

| Option | Description |
|--------|-------------|
| `-h`, `-help` | Show help and exit |
| `-a`, `-author` | Author filter (default: `git config user.email`) |
| `-c`, `-commit` | Starting revision for `git log` (default: `HEAD`) |
| `-s`, `-since` | Inclusive start date `YYYY-MM-DD` (default: today) |
| `-e`, `-until` | Inclusive end date `YYYY-MM-DD` (default: today) |
| `-x`, `-exclude` | Pathspec to exclude |
| `-g`, `-grep` | Only commits whose message matches text (case-insensitive) |

Flags accept `-flag=value` or `-flag value`.

```bash
git-ls -h
git-ls -since=2026-07-01 -until=2026-07-18 -exclude=vendor/
git-ls -grep=hotfix
git-ls -author=alice@example.com
```

#### `git-dif`

Runs `git-ls` with the same options, then opens matching files in `git difftool` against the chosen commit (`-c` / `-commit`, default `HEAD`). Prints a message if nothing matches.

```bash
git-dif -h
git-dif -since=2026-07-01 -c HEAD~3
git-dif -grep=hotfix
git-dif -author=alice@example.com
```

### `django_ref.sh`

Django scaffolding helpers. Provides the `make-django` command for generating a model and its DRF feature files into an existing app, following the conventions of the CPD Hub backend (`cpd-hub/backend`): `djangondor` helpers (`BaseTimestampModel`, `**NULLABLE` / `**NULLABLE_CHARFIELD`), a `managers.py` Manager class, `admin.py` registration, and a `api/` package with `serializers.py`, `filters.py`, `views.py` (`ModelViewSet` + `@extend_schema`), and `urls.py` (`DefaultRouter`). Permission classes follow the `shared_tools` pattern (`_DEF = api_settings.DEFAULT_PERMISSION_CLASSES`, `PERM_X = *_DEF, XClass`).

Python files are generated by [`django/model_scaffold.py`](django/model_scaffold.py), which runs with the project's virtualenv python (`.venv/bin/python` → `venv/bin/python` → `python3`) so `djangondor`, `shared_tools`, and `drf_spectacular` are detected. Generation is append-only and idempotent: existing models/registrations are left untouched.

#### `make-django`

| Subcommand | Description |
|------------|-------------|
| `make-django model [app.]Name [fields] [options]` | Scaffold a model + DRF feature files |
| `make-django help` | Show help and exit |

Run from anywhere inside a Django project — a parent directory containing `manage.py` (or a `backend/manage.py`, e.g. a repo root that also holds a `frontend/` folder). The model name is converted to PascalCase from any case (`site`, `milk_batch`, `milk-batch` → `Site`, `MilkBatch`).

Prefix `Name` with `app.` to pin the app, e.g. `farmers.site`. If the app does not exist it is created via `python manage.py startapp <app>` (after a confirmation, or automatically with `-y`). Without a dotted prefix you are prompted for the app (detected from the current directory if you are inside an app, otherwise listed from the project).

You are then prompted for the fields, base class, and each piece of scaffolding with `[Y/n]`:

| Feature | Generates |
|---------|-----------|
| Manager | `managers.py` with a `<Model>Manager`, wired as `objects` in the model |
| Admin | `admin.py` registration |
| Serializer / Viewset / Filterset | `api/serializers.py`, `api/views.py`, `api/filters.py` |
| URL registration | `api/urls.py` router entry |
| Permission | `permissions.py` (`PERM_<MODEL>` following the `shared_tools` pattern) |
| ETL | `data_etl/` package, `data_etl/queries/<sql_name>.sql`, and a query processing function in `data_etl/<model>_etl.py` (pandas or polars) |
| Management command | `management/commands/<app>.py` that runs the ETL (`python manage.py <app> [--sql-name ...]`) |
| Celery | worker task appended to `developer_console/tasks.py` (`@shared_task` + `run_tracked`), an `ExposedTaskName` entry in `developer_console/values.py`, and a crontab section in `configs/celery-beat.ini` |
| API client + TS | `frontend/src/Data/<app>/api.ts` using the cpd-hub `Tools/api` conventions, plus ambient interfaces in `frontend/typings/<app>.d.ts` |

| Option | Description |
|--------|-------------|
| `-y`, `--yes` | Non-interactive: create the app if needed and scaffold everything (DRF stack, ETL + pandas, command, Celery, TS client) with defaults |
| `--base CLASS` | Base model class (default: `BaseTimestampModel` when `djangondor` is installed, else `models.Model`) |

Field syntax (comma separated):

| Syntax | Generates |
|--------|-----------|
| `name` | `CharField(max_length=255)` |
| `name:Int` | `IntegerField` (aliases: Char, Text, Int, Float, Bool, Date, DateTime, JSON, Array, UUID, Slug, Email, URL, File, Image, Decimal, …) |
| `name:Type?` | nullable field (`**NULLABLE` / `**NULLABLE_CHARFIELD` with djangondor) |
| `owner:FK:User` | `ForeignKey('User', on_delete=models.SET_NULL)` (nullable) |
| `owner:FK:User?` | nullable FK (`on_delete=models.SET_NULL`) |
| `groups:M2M:Role` | `ManyToManyField('Role')` |
| `profile:O2O:User` | `OneToOneField('User')` |
| `name:CharField:80` | `CharField(max_length=80)` |
| `amount:Decimal:max_digits=10;decimal_places=2` | verbatim kwargs, `;`-separated (commas stay field separators) |

```bash
make-django model Farmer name,age:Int
make-django model farmers.site code,name:CharField:80
make-django model -y frost_index.Trial name,protocolOwner:FK:frost_index.User?,started:Date?
make-django model Region code,name:CharField:80 --base models.Model
```

The generator also accepts the flags directly via `django/model_scaffold.py`: `--root --app --name --fields --base --manager --admin --serializer --viewset --filterset --urls --permissions --permission-source --etl --etl-lib --sql-name --etl-function --command --command-name --celery --api-client --frontend-dir --typings-file --dry-run`.

Note: field options are `;`-separated (`amount:Decimal:max_digits=10;decimal_places=2`), so quote the fields string when passing it on a shell command line; typing at the prompt needs no quoting.

## Adding helpers

Create a new file ending in `_ref.sh` in this folder, define functions in it, then run `./init.sh` and select it so it is sourced from `~/.bashrc`.
